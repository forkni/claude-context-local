# SSCG canon re-pin — 2026-08-03 (`canon_C3`, post-C3/2a searcher-construction + config-metadata fixes)

Re-pins the SSCG canon after the ADR-0018-follow-on plan's Phase 1 (C3: extract
`build_hybrid_searcher`, guard `save_config` against leaking project overrides into global
config, fix the startup binding of the active project's `search_overrides.json`, delete the
orphaned `_switch_active_model`) and Phase 2 (2a: drop the two false `construction_baked` flags
on `bm25_weight`/`dense_weight`; 2b: migrate three probe scripts onto the `arm_overrides` seam).
None of these changes touch scoring, fusion, or reranking logic — they are construction
deduplication, a config-write bug fix, and metadata correctness — but every one of them edits
indexed source, and this project benchmarks against its own codebase. Per the originating plan,
capture ran only after all six commits landed (`65f2317`, `f86dced`, `c85d476`, `4d6de41`,
`0f8ff8d`, `a22ebe7`).

## Procedure

1. `audit_golden_dataset.py` — first run (pre-reindex) flagged one stale gold (Q90, kind
   mismatch on `mcp_server/search_factory.py::get_searcher`) against a stale live-index
   snapshot, not a dataset defect (confirmed by source inspection: `get_searcher` is a top-level
   function, never a method). Resolved by the mandatory reindex in step 2; re-run afterward was
   clean on both datasets (77/63 and 145/131 scored).
2. Full non-incremental reindex: `tools/batch_index.py --path . --mode force` — 201 files, 2310
   chunks (up from 2307 pre-Phase-1/2, +3 net from this plan's source edits; the corpus also
   carries several intervening commits already on `development` between ADR-0023's `canon_B1`
   capture and this one, so the delta below is not attributable to a single mechanism — same
   caveat ADR-0023 itself states for its own predecessor delta).
3. Two rounds each of 63q, 131q, and the F-via-similar view, `PYTHONHASHSEED=0`
   (harness self-pins per ADR-0021):
   - `sscg_canon_c3_63q_r{1,2}.json`
   - `sscg_canon_c3_131q_r{1,2}.json` (`--golden-dataset evaluation/golden_dataset_expanded.json`)
   - `sscg_canon_c3_fview_r{1,2}.json` (`--f-via-similar`)
4. **0 flips**, all three pairs, confirmed via `run_sscg_benchmark.py --compare`: every
   aggregate metric and every per-query row identical between rounds except `latency_ms`
   (round-to-round timing noise).

## Delta vs. `canon_B1` (ADR-0023, mrr 0.8249, recall@10 0.7655, recall@20 0.8436, pool_hit 1.0)

mrr +0.0099, recall@10 +0.0264, recall@20 +0.0119, ndcg@5 +0.0168, line_recall +0.0106,
line_iou +0.0139, file_recall@10 +0.0163, hard_negative_intrusion_rate −0.0093, pool_hit_rate
unchanged at 1.0. Small, uniformly positive across ranking-quality metrics — consistent with
ordinary corpus drift (2292→2310 chunks across the commits between the two captures) plus the
config-metadata correctness fixes in Phase 2a eliminating spurious reranker-model reloads on
every weight-arm run (a probe/benchmark-efficiency effect, not a scoring-path change — Phase 2a
never touches fusion, ranking, or reranking code). Not attributable to a single mechanism; see
ADR-0024.

## Comparability

Not comparable to the published `0.7987` (63q) / `0.8502` (mislabeled F-view whole-aggregate)
still in `CLAUDE.md`/`README.md`/`docs/BENCHMARKS.md`/`docs/HYBRID_SEARCH_CONFIGURATION_GUIDE.md`/
`docs/VERSION_HISTORY.md` before this record — those predate both `canon_B1` (ADR-0023) and this
capture, and were never updated when `canon_B1` landed. This record and its accompanying ADR-0024
supersede both `0.7987` and `canon_B1` as the current published baseline.

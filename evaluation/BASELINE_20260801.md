# Fresh SSCG baseline — 2026-08-01 (post C2/ADR-0019, new metric suite)

Establishes the first post-refactor baseline carrying the new metric suite (graded NDCG,
Acc@k, file-level rollup, hard-negative intrusion — `21a438c`) after two commits landed mid-run:
the C2 retrieval-request refactor (`030325d`, ADR-0018) and the intent-adaptive-fusion-weights
rejection/deletion (`c03e0b4`, ADR-0019). All runs use `run_sscg_benchmark.py --project-path .`
at k=10, default config (`bm25_weight 0.35 / dense_weight 0.65`, `bm25_reserved_slots 0`,
`query_expansion.enabled False`), plus one live `run_mcp_pipeline_eval.py --k 7` run through the
orchestrator/multi-hop path. Raw per-run JSONs: `benchmark_results/` (gitignored, local).

## Pairing validity — two commits, one baseline

Runs exist under two naming series that must be pooled to get full replicate counts:

- `sscg_baseline_20260801_{canonical,expanded}_r*` — 2 canonical + 1 expanded run, taken
  **before** `030325d`/`c03e0b4` landed (this session was paused mid-run).
- `ab_intent/{63q,96q}_base_r{1,2,3}` — 3 replicates × 2 datasets, ADR-0019's own base arm
  (`intent_adaptive_weights` off — i.e. the deployed default), run **after** both commits, with
  the full new-metric suite (11/11 keys).

Both series agree within the ±0.02 noise band: canonical 0.8012 / 0.7995 (pre) vs
0.8012 / 0.7855 / 0.8094 (post, μ 0.7987); expanded 0.6945 (pre) vs 0.6771 / 0.6872 / 0.6803
(post, μ 0.6815). `SESSION_LOG.md`'s C2-verification session measured the stronger form of this
directly with a **same-code control**: a second 94q run on unchanged post-C2 code landed at MRR
0.683 vs the first run's 0.701 — an 0.018 same-code spread, 18/94 queries flipping, `pool_size`
shifting on nearly every one (Q77 31→30, Q117 18→17, Q127 26→21). The ±0.02 band is therefore a
measured property of this harness's run-to-run variance, not a convention, and both the
pre/post-refactor delta and the pre/post-ADR-0019 delta sit inside it. **The two series are
pooled below**; the ADR-0019 base arms serve double duty as this baseline's 3-replicate expanded
run, and no separate `expanded_r2` was run.

## Comparability breaks

- **94q ≠ the old 96q `postcommunity` baseline.** Q109/Q110 were removed from
  `golden_dataset_expanded.json` on 2026-07-31; any historical `96q` MRR predating that date is
  not directly comparable to the 94q numbers here despite the shared file naming.
- **Index snapshot.** All Track-1 runs above (`sscg_baseline_*`, `ab_intent/*`) were taken
  against the 10:33 index snapshot (2258 chunks / 196 files). The current live index (checked
  post-run, `last_indexed_time` 2026-08-01T21:31, after this session's `run_mcp_pipeline_eval.py`
  execution) carries 2259 chunks / 196 files — a one-chunk delta, immaterial, recorded rather
  than re-run for.
- **SDK v2 corpus delta.** `3ea4718` (MCP SDK v1→v2 migration, DSPy eval-subsystem removal —
  13 files / 4,849 lines) landed between the old README-cited baselines and this one; corpus
  composition is not identical to any pre-`3ea4718` benchmark.
- **Pipeline-eval reference numbers (MRR 0.700 / Recall@7 0.696)** predate the multi-hop +
  ego-graph + reranker orchestrator path this run exercises — the 0.90/0.77 result is not a
  regression check against those, only a sanity range (both far exceed the old searcher-only
  floor, as expected for a strictly more capable retrieval path).
- **Index provenance (added after the fact).** Every number above was measured against the
  10:33 index snapshot (2,259 chunks / 196 files) described in the previous bullet. That index
  was later destroyed by the embedder A/B harness incident (see
  `EMBEDDER_GEMMA_AB_20260801.md`) and rebuilt via a full force reindex: 2,251 chunks / 195
  files, the one-file delta being the deleted harness itself. Chunking and embedding are
  deterministic over an unchanged corpus, so these baselines stand as measured — but they now
  describe a snapshot one file smaller than the live index, and that provenance belongs on the
  record rather than silently assumed.
- **H-category promotion (2026-08-02).** `golden_dataset_expanded.json` grew from 108 to 145
  queries (94 to 131 non-D) when 37 commit-mined bug-fix-localization queries were promoted as
  category H (`scripts/benchmark/merge_h_queries.py`). Every "expanded" number above predates
  this promotion and is not directly comparable to any post-promotion expanded run; see the
  addendum below for the new expanded baseline.

## Addendum: H-category promotion & expanded re-baseline (2026-08-02)

68 commit-mined candidates (`evaluation/commit_mined_candidates.json`, category H) were
paraphrased and graded live at k=10 across 2 rounds
(`grade_candidate_queries.py --candidates`, transcripts in
`benchmark_results/grade_candidates_round{1,2}.txt`). 37 passed both rounds and were promoted;
31 were excluded — most for `pool_miss`/invalid golds, one (H042) as an exact duplicate of H041,
and 4 (H035, H060, H061, H068) despite ranking in the top-10 in round 1: round 2, run against the
**same unchanged live index**, dropped all four to `pool_miss`. This is reranker
batch-composition non-determinism (the bf16 `jinaai/jina-reranker-v3` model), not a retrieval
regression — but it means a single grading run is not sufficient evidence to promote a
boundary-riding query into a fixed-membership golden set. All 37 promoted golds are graded
relevance 3 as-is (trusting the commit-mining ground truth; no manual sibling grade-2
embellishment this round). Splits: train 25 / val 6 / test 6.

Promotion is a comparability break: the expanded dataset grew 108→145 queries (94→131 non-D).
Re-baselined 2 rounds at the same comparability config (`bm25_weight 0.35 / dense_weight 0.65`,
`bm25_reserved_slots 0`, `query_expansion.enabled False`), both PASS on all gating thresholds and
within the established ±0.02 noise band of each other:

| Run | MRR | recall@5 | recall@10 | ndcg@5 | hit_rate@5 | pool_hit_rate |
|---|---|---|---|---|---|---|
| `expanded_h_r1` (131q) | 0.6591 | 0.6363 | 0.7669 | 0.6001 | 0.8855 | 0.9695 |
| `expanded_h_r2` (131q) | 0.6587 | 0.6338 | 0.7633 | 0.6003 | 0.8855 | 0.9542 |

New-metric suite (r1 / r2): `ndcg@5_graded` 0.6127 / 0.6142, `file_acc@5` 0.7328 / 0.7023,
`file_recall@5` 0.8531 / 0.8360, `hard_negative_intrusion_rate` 0.2245 / 0.2041, `recall@20`
0.8179 / 0.8108, `recall@50` 0.8209 / 0.8134. Both runs: audit clean (0 stale golds across both
datasets) and the drift guard green (2213 passed, 0 failed) before either run.

Result: the expanded dataset absorbs 37 new bug-fix-localization queries at a slightly lower
MRR than the pre-promotion 94q baseline (0.659 vs 0.6815) — expected, since H queries are a
harder, more specific category (single-file, ≤2 golds, commit-mined from real fixes rather than
hand-written) — with no destabilization of the existing categories and no drift-guard or audit
regression.
